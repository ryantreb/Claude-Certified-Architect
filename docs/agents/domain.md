# Domain Docs

This is a single-context repository. Before exploring a domain area, engineering
skills should read:

- `CONTEXT.md` at the repository root;
- relevant architectural decisions under `docs/adr/`.

If either source does not exist, proceed without requiring it to be created.

## Vocabulary

Use domain terms as defined in `CONTEXT.md` when naming issues, tests,
hypotheses, and implementation concepts. Avoid synonyms that the glossary marks
as incorrect. If a required concept is absent, note the gap rather than silently
inventing project terminology.

## Architectural decisions

Surface any conflict with an existing ADR explicitly. Do not silently override
an accepted decision.
